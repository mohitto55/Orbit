# 도메인 점검 기능 명세

주기적으로 도메인 검토를 요청하고, 최근 작업 대화와 도메인을 나란히 보여준다. 판단은 사람이 한다. (P3 해결)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| DR-F01 | 검토 알림 | 도메인 반영을 미루지 않게 한다 | AC1: 설정 주기가 되면 검토 요청 알림이 뜬다<br>AC2: 지난 검토 이후 새 세션이 없으면 알리지 않는다<br>AC3: 언제든 수동으로 검토를 시작할 수 있다 | 초안 |
| DR-F02 | 검토 대상 모으기 | 볼 대화만 추린다 | AC1: 지난 검토 이후 세션이 날짜, 첫 요청, 길이, 관련 커밋과 함께 표시된다<br>AC2: 이미 검토한 세션은 제외된다<br>AC3: "도메인 로직 바뀜"으로 완료된 Task와 연결된 세션이 위에 표시된다 | 초안 |
| DR-F03 | 나란히 보기 | 대화와 도메인을 쉽게 비교한다 | AC1: 왼쪽에 대화, 오른쪽에 도메인 트리와 본문이 표시된다<br>AC2: 대화 속 도메인·개념 이름이 강조되고, 클릭하면 오른쪽 해당 도메인으로 이동한다 | 초안 |
| DR-F04 | 표시 남기기 | 사람의 판단을 다음 행동으로 잇는다 | AC1: 대화 일부를 골라 `도메인 반영` / `할 일` / `지식` 중 하나로 표시할 수 있다<br>AC2: `도메인 반영`은 발췌가 첨부된 변경 요청으로 도메인에 간다<br>AC3: `할 일`은 Inbox로, `지식`은 지식 초안으로 간다 | 초안 |
| DR-F05 | 검토 마치기 | 검토 범위를 확정한다 | AC1: 마치면 회차 파일이 남고 본 세션이 검토됨으로 기록된다<br>AC2: 표시가 없어도 마칠 수 있다 | 초안 |
| DR-F06 | 검토 이력 | 과거 검토 결과를 추적한다 | AC1: 회차별로 나온 변경 요청·할 일·지식이 표시된다 | 초안 |
| DR-F07 | AI 점검 실행 | 도메인이 실제 작업과 맞는지 AI가 점검해 놓친 변화를 찾는다 | AC1: 점검 요청문에 현재 도메인 문서와 지난 점검 이후의 작업 대화·커밋이 들어간다<br>AC2: AI 응답에서 결과(요약, 항목)를 읽는다. 형식이 어긋나도 JSON을 찾아 읽는다<br>AC3: 점검 결과가 기록되고, 다음 점검은 이번 점검 이후를 기준으로 한다<br>AC4: AI 실행이 실패하면 실패 기록만 남고 점검 기준 시각은 바뀌지 않는다<br>AC5: Claude Code와 Codex 중 골라서 실행할 수 있다 | 초안 |
| DR-F08 | 점검 항목 판단 | AI 제안을 사람이 걸러서 반영한다 | AC1: 받아들인 항목은 종류에 따라 도메인 변경 요청 / Inbox / 지식 초안이 된다<br>AC2: 무시한 항목은 기록만 남는다<br>AC3: 항목마다 근거(대화 인용, 커밋)가 함께 보인다 | 초안 |

## 규칙

- 앱은 차이를 판단하거나 도메인을 고치지 않는다.
- 세션 원본은 복사하지 않고 위치만 기록한다. 표시한 발췌만 저장한다.

## 미결정 사항

- 기본 검토 주기
- 한 회차에 보여줄 세션 수 상한
