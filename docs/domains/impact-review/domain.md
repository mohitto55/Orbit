# 변경 검토

> 해결 문제: P1

## 역할

변경에 대해 사람이 결정할 것을 한곳에 모은다. 두 방향이 있다.

- **변경 요청** (바깥 → 도메인): 도메인 문서를 이렇게 고치자는 요청을 보고, 반영 완료 또는 반려로 닫는다.
- **확인할 문서** (도메인 → 아래): 위 층에 큰 변경이 생기면 그것을 기준으로 한 아래 층(기능 명세 표, 설계, 테스트)을 찾아 "확인 필요"를 표시하고, 사람의 판단을 기록한다. 확인 항목마다 원인(위 층의 큰 변경) → 영향(아래 층 문서)과, 그 문서가 어느 도메인 것인지를 함께 보여준다.

## 용어

이 도메인(바운디드 컨텍스트) 안에서의 뜻이다. 같은 단어도 다른 도메인에서는 뜻이 다를 수 있다.

| 용어 | 뜻 | 비고 |
|---|---|---|
| 위 층 / 아래 층 | 4층 구조에서 기준이 되는 쪽 / 기준을 삼는 쪽 |  |
| 검토 (ImpactReview) | 큰 변경 1건에 대해 열리는 확인 묶음 |  |
| 확인 항목 (ReviewItem) | 아래 층 대상 1개에 대한 확인 요청 | 예전 이름은 확인표시 |
| 확인 대상 | 바뀐 것을 **직접** 기준으로 삼은 아래 층 문서·테스트 |  |
| 참고 목록 | 간접 영향(하위 도메인, 의존 도메인)의 표. 확인 항목 없이 보여주기만 한다 |  |
| 비교 (diff) | 원인이 된 큰 변경의 변경 전·후를 줄 단위로 보여주는 읽기 전용 보기 | 저장 시 스냅샷만 쓴다. 스냅샷이 없는 예전 변경은 비교할 수 없다 |
| 변경 요청 | 도메인 문서를 이렇게 고치자고 들어온 요청. 반영 완료 또는 반려로 닫는다 | 바깥 → 도메인 방향 |
| 판단 | `수정 필요` / `변경 불필요` / `보류` | 사람만 내린다 |

## 모델

이 도메인이 소유한 개념의 상태·행위·불변식과 관계다. 응용 서비스의 호출 순서는 적지 않는다 (그건 설계에).

| 개념 | 종류 | 상태·행위 | 불변식 | 관계 | 코드 |
|---|---|---|---|---|---|
| 검토 | Aggregate | 원인 변경, 확인 항목들, 참고 목록 / 열기 | 큰 변경 1건에 하나. 두 번 열리지 않는다 | 원인 [[도메인/ChangeSet]]<br>소유 [[확인 항목]] | `openReview` |
| 확인 항목 | Entity | 대상, 층, 판단, 메모 / 판단 | 판단은 사람만 내린다 | 확인 [[기능 명세/기능 명세 표]]<br>확인 [[설계/설계]] | `decide` |
| 변경 요청 | Entity | 대상 도메인, 제안, 근거, 상태 / 닫기 | 이미 닫은 요청은 다시 닫을 수 없다 | 대상 [[도메인/도메인]] | `resolveRequest` |

## 하지 않는 것

- 확인 대상 문서나 테스트를 직접 수정
