# 변경 검토 기능 명세

위 층에 큰 변경이 생기면 그것을 기준으로 한 아래 층에 "확인 필요"를 표시하고, 사람의 판단을 기록한다. (P1 해결)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| IR-F01 | 검토 열기 | 큰 변경의 영향을 빠짐없이 잡는다 | AC1: 큰 변경일 때만 검토가 열린다. 작은 변경은 열리지 않는다<br>AC2: 확인 대상은 아래 표의 규칙을 따른다<br>AC3: 대상마다 ReviewItem이 하나씩 생기고 검토 파일이 남는다 | 초안 |
| IR-F02 | 참고 목록 | 간접 영향도 놓치지 않되 확인 부담은 늘리지 않는다 | AC1: 변경된 도메인의 하위 도메인, 의존하는 도메인의 표는 확인표시 없이 참고 목록에만 나온다<br>AC2: 참고 목록에서 확인표시로 올릴 수 있다 | 초안 |
| IR-F03 | 확인 화면 | 관계 여부를 빠르게 판단한다 | AC1: 위 층 변경 내역(요약, 이전/이후 차이)과 아래 층 내용이 나란히 표시된다<br>AC2: 관계없는 항목은 클릭 한 번(변경 불필요)으로 처리된다 | 초안 |
| IR-F04 | 판단 기록 | 판단에 따라 다음 행동을 이어준다 | AC1: 판단은 아래 표의 결과로 이어진다<br>AC2: 판단 날짜와 메모가 기록된다 | 초안 |
| IR-F05 | 확인 대기 목록 | 남은 확인을 잊지 않는다 | AC1: 처리되지 않은 ReviewItem이 층별로 모여 표시된다<br>AC2: 첫 화면에 남은 개수가 표시된다 | 초안 |
| IR-F06 | 검토 겹침 처리 | 같은 대상에 확인표시가 쌓이지 않게 한다 | AC1: 미처리 ReviewItem이 있는 대상에 같은 출처의 큰 변경이 또 생기면 새 항목 대신 기존 항목에 변경 내역이 덧붙는다 | 초안 |
| IR-F07 | 검토 이력 | 과거 판단을 추적한다 | AC1: 대상 문서·도메인 기준으로 과거 검토와 판단이 표시된다 | 초안 |
| IR-F08 | 도메인 변경 요청 처리 | 도메인을 고치자는 요청을 한곳에서 보고 결정한다 | AC1: 들어온 변경 요청이 출처(AI 점검·대화 직접 보기·할 일 완료), 대상 도메인, 제안, 근거와 함께 목록에 보인다<br>AC2: 반영 완료 또는 반려로 닫을 수 있고, 메모와 함께 기록된다. 이미 닫은 요청은 다시 닫을 수 없다<br>AC3: 대상 도메인 문서 편집 화면으로 바로 이동할 수 있다 | 초안 |

## 확인 대상 규칙

| 위 층 변경 | 확인 대상 (아래 층) |
|---|---|
| 도메인 | 그 도메인의 기능 명세 표 |
| 기능 명세 표 (바뀐 기능·AC) | 그 기능을 기준으로 한 기능별 설계, 그 AC에 연결된 테스트 |
| 시스템 공통 설계 (바뀐 섹션) | 그 섹션을 참조한 기능별 설계 |

## 판단과 결과

| 대상 | 판단 | 결과 |
|---|---|---|
| 기능 명세 표·설계 | 수정 필요 | 해당 문서 편집 화면을 열고, 저장하면 기준 버전이 갱신된다 |
| | 변경 불필요 | 기준 버전만 갱신된다 (내용 유지) |
| | 보류 | `spec-sync` / `design-sync` Task가 생성된다 |
| 테스트 | 수정 필요 | `test` Task가 생성된다 |
| | 변경 불필요 | 테스트 연결의 확인 버전이 갱신된다 |

## 규칙

- 확인표시는 사람만 처리할 수 있다.
- 보류된 대상은 생성된 Task가 끝날 때까지 낡음 상태를 유지한다.
- 검토 기록은 지우지 않는다.

## 미결정 사항

- 참고 목록의 범위 (하위 1단계만 / 전체 하위)
