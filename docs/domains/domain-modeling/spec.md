# 도메인 기능 명세

도메인과 하위 도메인, 그 안의 개념을 정의하고 버전을 관리한다. (1층)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| DM-F01 | 도메인 만들기 | 도메인·하위 도메인을 정의한다 | AC1: 이름, 설명, 도메인 유형(Core/Supporting/Generic), 상위 도메인(선택)으로 생성된다<br>AC2: 생성 시 불변 id가 정해지고 버전은 v1이다<br>AC3: 같은 상위 아래 형제와 이름이 겹치면 생성이 거부된다 | 초안 |
| DM-F02 | 개념 만들기 | 도메인 안의 개념을 정의한다 | AC1: 개념은 정확히 하나의 도메인에 속한다<br>AC2: 종류는 Entity / Value Object / Aggregate / Event / Policy / Term 중 하나다<br>AC3: 개념 추가·수정·삭제는 소속 도메인의 변경으로 기록된다 | 초안 |
| DM-F03 | 변경 기록 | 도메인이 왜, 얼마나 바뀌었는지 남긴다 | AC1: 저장 시 변경 크기(큰/작은)와 변경 요약을 입력하지 않으면 저장되지 않는다<br>AC2: 저장하면 버전이 1 오르고 ChangeSet이 남는다<br>AC3: 저장 직전 바뀐 부분(diff)을 보여준다<br>AC4: ChangeSet에 출처(직접 수정 / 작업 대화 / Task)가 기록된다 | 초안 |
| DM-F04 | 하위 도메인 이동 | 도메인 계층을 재구성한다 | AC1: 이동은 항상 큰 변경으로 기록된다<br>AC2: 자기 자신이나 자기 하위로 옮기면 거부된다 | 초안 |
| DM-F05 | 도메인 폐기 | 더 쓰지 않는 도메인을 정리한다 | AC1: 하위 도메인이나 활성 기능 명세가 남아 있으면 삭제가 거부되고 이유가 표시된다<br>AC2: 삭제 대신 `폐기됨` 상태로 바꿀 수 있다 | 초안 |
| DM-F06 | 변경 이력 보기 | 도메인의 변화 과정을 추적한다 | AC1: 버전별 변경 크기, 요약, 날짜, 출처가 표시된다<br>AC2: 두 버전을 골라 차이를 볼 수 있다 | 초안 |
| DM-F08 | 용어 사전 | 바운디드 컨텍스트마다 용어의 뜻을 고정하고 나중에 참조한다 | AC1: 도메인마다 용어 섹션(용어 / 뜻 / 비고)을 편집할 수 있고, 각 용어는 Term 개념으로 저장된다<br>AC2: 용어 검색 시 같은 용어를 가진 모든 도메인과 각 도메인에서의 뜻이 나란히 표시된다<br>AC3: 다른 도메인에 같은 이름의 용어가 있으면 편집 화면에 "다른 컨텍스트에도 있음"이 표시된다<br>AC4: 용어 추가·수정은 소속 도메인의 변경으로 기록된다 | 초안 |

## 규칙

- 하위 도메인의 상위는 정확히 하나다. 상위 관계에 순환이 생기면 안 된다.
- 상위가 다르면 같은 이름도 별개 도메인이다. 화면에는 경로를 붙여 구분한다 (`주문 › 고객`).
- 이력은 지우지 않는다.

## 미결정 사항

- 하위 도메인이 있는 최상위 도메인도 버전을 매길지
