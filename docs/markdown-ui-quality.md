# Markdown UI 품질 검사

`npm run test:ui`는 앱을 빌드한 뒤 Playwright로 실제 Electron/Chromium 창을 실행한다. 임시 프로젝트와 별도 사용자 프로필을 사용하며, 설치된 Orbit의 데이터에는 접근해 수정하지 않는다. 테스트용 화면이나 IPC 모킹 없이 실제 preload, renderer, 파일 저장 API를 거친다.

Linux의 화면 없는 환경에서는 `xvfb-run -a npm run test:ui`로 실행한다. Electron에 포함된 Chromium을 사용하므로 Playwright 브라우저를 따로 설치할 필요는 없다.

## 검사 범위

| 범주 | 실제 UI에서 확인하는 내용 |
| --- | --- |
| 제목 | ATX 1–6, Setext, 앵커 숨김, 원문 보존 |
| 본문 | 한글·Unicode, 문단, 줄바꿈·빈 줄, 이스케이프 |
| 인라인 서식 | 굵게, 기울임, 취소선, 중첩 서식, 인라인 코드 |
| 목록 | 순서·비순서·중첩 목록, 체크 상태, Enter로 항목 이어 쓰기와 종료 |
| 인용·코드 | 중첩 인용, 백틱·틸드 코드 블록, 들여쓴 코드, 코드 안 문법을 그대로 표시 |
| 표 | 앞 문단과의 간격, 셀 클릭 위치, 편집 후 다시 렌더링, 열 정렬, 이스케이프된 파이프, 셀 안 서식·줄바꿈·이미지 |
| 복잡한 표 | 여러 표, 인용·목록 안 표, 긴 표의 가상 스크롤, 긴 셀의 표 내부 가로 스크롤 |
| 링크 | 일반·참조·자동 링크, 위키 링크와 별칭 |
| HTML | 안전한 블록, details, pre, 구분선, 위험한 태그·속성·URL 제거 |
| 이미지 | 상대·절대·file URL·한글 경로, 참조형, HTML, 표 안 이미지, 로컬 HTTP 서버, data URI, 실제 디코딩, 설명 편집, 깨진 경로 복구 |
| 이미지 크기·확대 | 모서리 드래그와 비율 유지, 키보드 크기 조절, 동일 이미지의 개별 변경, 드래그 취소·실행 취소·초기화·저장·재열기, 표 구분자 보존, 확대 창의 휠 줌·원본 100%·드래그 이동·Escape |
| 입력 | Chromium IME 조합 경로, Markdown/CRLF 붙여넣기, 실행 취소·다시 실행 |
| 화면 | 너비 960/1360px, 높이 680/860px, 밝은/어두운 테마, 체크박스 크기·왼쪽 위치·중첩 들여쓰기, 문서 폭 넘침, 대화상자와 본문 각각의 스크롤 |
| 저장 | 할 일, 새 도메인, 도메인 역할, 개별 설계, 공통 설계, 지식, 스킬, 변경 요청 수정안의 실제 파일과 재열기 |

문법별 사례는 `tests/ui/markdown-cases.ts`, 배치·편집 검사는 `markdown.spec.ts`, 이미지·IME 검사는 `images-and-input.spec.ts`, 각 문서 화면의 저장 검사는 `documents.spec.ts`에 있다. 본문 내부의 문법·줄바꿈·공백·체크 상태를 저장 전후 대조한다. 파일 저장 계층의 기존 개행 정규화와 본문 바깥 공백 정책은 유지한다.

IME 검사는 CDP로 Chromium의 composition 이벤트 경로를 검증한다. 각 OS의 실제 한국어 입력기 후보창이나 키보드 드라이버까지 검증하는 것은 아니다. 수식·Mermaid 등 앱이 지원한다고 정의하지 않은 확장 문법은 이 검사 범위에 포함하지 않는다.

## 실패 판정과 증거

- 가상 DOM의 노드 존재 여부에 더해 실제 브라우저의 좌표, 크기, 정렬, 스크롤, 이미지 디코딩, 키보드 입력을 검사한다.
- 표 위치 회귀는 8행 표가 앞 문단에서 약 1,074px 떨어지는 기존 버전에서 실패하도록 먼저 확인했다. 한 빈 줄 뒤의 간격은 60px 미만이어야 한다.
- 창 크기와 OS에 따라 폰트 픽셀이 달라지므로 핵심 배치는 기하 조건으로 판정한다. 스크린샷을 자동으로 새 정답으로 채택하지 않는다.
- 각 사례의 스크린샷, JUnit XML, HTML 보고서를 `test-results/`에 남긴다. 실패 시 동작·DOM·화면이 포함된 Playwright trace도 저장한다.
- 렌더러 예외와 예기치 않은 console error는 실패다. 이미지 로드 실패는 별도 복구 시나리오로 검사한다.
- CI에서 UI 검사가 실패하면 작업이 실패한다. 릴리스도 Windows/macOS/Linux 각각 UI 검사를 통과해야 패키징하고, 세 OS가 모두 성공해야 공개된다.

보고서: `npx playwright show-report test-results/ui-report`

실패 재현: `npx playwright test -g '테스트 이름'`

추적 열기: `npx playwright show-trace test-results/ui/<실패한 테스트>/trace.zip`
