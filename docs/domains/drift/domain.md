# 도메인 점검

> 해결 문제: P3

## 역할

지난 점검 이후의 작업 대화와 커밋을 현재 도메인 문서와 함께 AI(Claude Code·Codex)에게 주고, 도메인이 실제 작업과 맞는지 점검시킨다. AI는 맞지 않는 곳을 근거와 함께 제안만 하고, 사람이 항목마다 받아들이거나 무시한다. 대화를 사람이 직접 읽고 표시를 남길 수도 있다.

## 용어

이 도메인(바운디드 컨텍스트) 안에서의 뜻이다. 같은 단어도 다른 도메인에서는 뜻이 다를 수 있다.

| 용어 | 뜻 | 비고 |
|---|---|---|
| 세션 (WorkSession) | Claude Code / Codex 대화 하나 |  |
| AI 점검 (AiCheck) | 지난 점검 이후의 대화·커밋과 도메인 문서를 AI에게 주고 결과(요약, 점검 항목)를 받는 한 번의 실행 |  |
| 점검 항목 (Finding) | AI가 근거와 함께 낸 제안 하나: `도메인` / `할 일` / `지식` | 표시가 아니다. 사람이 받아들여야 변경 요청·Inbox 항목·지식 초안이 되고, 무시하면 기록만 남는다 |
| 검토 회차 (DriftCheck) | 검토 한 번. 대상 기간, 본 세션, 결과를 기록 |  |
| 검토 주기 | 검토 요청 알림 간격. 프로젝트 설정 |  |
| 표시 (Mark) | 사람이 대화 일부에 남기는 판단: `도메인 반영` / `할 일` / `지식` | 앱과 AI는 표시를 만들지 않는다 |
| 발췌 | 표시한 대화 부분. 세션 원본 대신 이것만 저장 |  |
| 검토됨 | 한 회차에서 이미 본 세션. 다음 회차에서 제외 |  |

## 모델

이 도메인이 소유한 개념의 상태·행위·불변식과 관계다. 응용 서비스의 호출 순서는 적지 않는다 (그건 설계에).

| 개념 | 종류 | 상태·행위 | 불변식 | 관계 | 코드 |
|---|---|---|---|---|---|
| AI 점검 | Aggregate | 대상 기간, 본 세션, 요약 / 실행 | 실패하면 점검 기준 시각은 바뀌지 않는다 | 읽음 [[세션]]<br>소유 [[점검 항목]] | `runAiCheck` |
| 점검 항목 | Entity | 종류, 제안, 근거, 상태 / 받아들임, 무시 | 한 번 처리한 항목은 다시 처리할 수 없다 | 만듦 [[변경 검토/변경 요청]] | `decideFinding` |
| 세션 | Entity | 에이전트, 대화, 갱신 시각 |  |  | `readSessionMessages` |

## 하지 않는 것

- 도메인 문서를 직접 수정 (AI도 제안만 한다)
- 사람의 판단 없이 AI 제안을 반영
- 근거 없는 추측을 항목으로 남기기
