# Verification 기능 명세

수용 기준과 테스트 코드를 연결하고, 테스트를 실행해 결과를 요구사항 단위로 보여준다. (4층, P4 해결)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| VR-F01 | 테스트 연결 찾기 | 어떤 테스트가 어떤 요구사항을 검증하는지 안다 | AC1: 저장소의 테스트 코드에서 `[기능ID-AC번호]` 형식의 ID를 찾아 연결한다<br>AC2: 테스트 하나가 여러 AC를, AC 하나가 여러 테스트를 가질 수 있다<br>AC3: 존재하지 않는 AC ID를 가리키는 테스트는 "잘못된 연결"로 표시된다 | 초안 |
| VR-F02 | 테스트 실행 | 요구사항이 지켜지는지 확인한다 | AC1: 프로젝트 설정의 테스트 명령으로 전체 실행할 수 있다<br>AC2: 기능 하나 또는 도메인 하나에 연결된 테스트만 골라 실행할 수 있다<br>AC3: 실행 중 출력이 실시간으로 보이고, 중단할 수 있다 | 초안 |
| VR-F03 | 결과 읽기 | 언어·도구와 관계없이 결과를 모은다 | AC1: JUnit XML 결과 파일을 읽어 테스트별 통과/실패/건너뜀을 기록한다<br>AC2: 결과 파일이 없거나 읽을 수 없으면 실행 실패로 표시하고 원인 출력을 보여준다 | 초안 |
| VR-F04 | 요구사항 단위 결과 | 표에서 요구사항별 상태를 본다 | AC1: AC마다 통과 / 실패 / 테스트 없음 / 미실행 중 하나로 표시된다<br>AC2: AC에 연결된 테스트가 하나라도 실패하면 그 AC는 실패다<br>AC3: 도메인별·전체 검증률(통과 AC / 활성 AC)이 표시된다 | 초안 |
| VR-F05 | 검증 기준 확인 | 바뀐 요구사항을 옛 테스트가 통과시키는 상황을 막는다 | AC1: 테스트 연결마다 마지막으로 확인한 표 버전이 기록된다<br>AC2: 연결된 AC에 큰 변경이 생기면 해당 테스트에 확인표시가 뜬다 (Impact Review)<br>AC3: 확인표시가 처리되기 전까지 통과해도 "확인 필요"로 표시된다 | 초안 |
| VR-F06 | Task로 넘기기 | 빠진 테스트와 실패를 놓치지 않는다 | AC1: 테스트 없는 AC에서 `test` 유형 Task를 만들 수 있다<br>AC2: 실패한 AC에서 `bug` 유형 Task를 만들 수 있다<br>AC3: 만든 Task에 AC ID가 연결된다 | 초안 |
| VR-F07 | 실행 이력 | 검증 상태의 변화를 본다 | AC1: 실행마다 시각, 커밋, 결과 요약이 기록된다<br>AC2: 이전 실행 대비 새로 실패한 AC가 강조된다 | 초안 |

## 규칙

- 앱은 테스트 코드를 쓰거나 고치지 않는다.
- 테스트 결과를 해석하지 않고 그대로 보여준다.
- 실행 결과 원본은 캐시에 두고, 요약(AC별 상태, 실행 이력)만 md로 남긴다.

## 미결정 사항

- 실행 이력을 몇 회까지 보관할지
- 파일 변경 시 자동으로 관련 테스트를 실행할지
