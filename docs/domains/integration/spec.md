# 연동 기능 명세

GitHub, Claude Code, Codex, 테스트 실행기와 연결한다. 바깥 형식을 앱 내부 개념으로 바꾸는 번역층이다.

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| IN-F01 | 연결 상태 | 무엇이 연결됐는지 안다 | AC1: GitHub 인증 여부와 원격 주소가 표시된다<br>AC2: Claude Code / Codex 설치 여부와 세션 폴더 발견 여부가 표시된다<br>AC3: 테스트 명령 설정 여부가 표시된다 | 초안 |
| IN-F02 | GitHub 인증 | 별도 설정 없이 GitHub를 쓴다 | AC1: 설치된 `gh` CLI 인증을 우선 사용한다<br>AC2: 없으면 토큰을 입력받는다<br>AC3: 인증 정보는 데이터 폴더에 저장되지 않는다 | 초안 |
| IN-F03 | Issue 연동 | Task와 Issue를 잇는다 | AC1: 요청 시 Issue를 만들고 번호를 돌려준다<br>AC2: 앱을 열 때와 수동 새로고침 때 연결된 Issue 상태를 가져온다 | 초안 |
| IN-F04 | PR 연결 | 작업 결과를 문서에 잇는다 | AC1: PR 제목·본문의 기능·Task id를 찾아 해당 문서에 PR 링크를 붙인다 | 초안 |
| IN-F05 | 세션 가져오기 | 작업 대화에 대화를 넘긴다 | AC1: 현재 프로젝트 폴더에서 진행된 세션만 찾는다<br>AC2: 시작 시각, 첫 요청, 대화 내용이 WorkSession 형식으로 넘어간다<br>AC3: 원본 세션 파일은 바뀌지 않는다 | 초안 |
| IN-F07 | 테스트 실행기 | 테스트가 테스트를 돌린다 | AC1: 설정된 테스트 명령을 프로젝트 폴더에서 실행한다<br>AC2: 대상 테스트를 좁히는 인자(필터)를 넘길 수 있다<br>AC3: 실행 출력을 실시간으로 전달하고, 중단 요청을 받으면 프로세스를 종료한다<br>AC4: 결과 JUnit XML 파일 위치를 테스트에 넘긴다 | 초안 |
| IN-F08 | 형식 변경 대응 | 외부 형식이 바뀌어도 앱이 멈추지 않는다 | AC1: 세션·결과 파일을 읽지 못하면 오류가 표시되고 다른 기능은 계속 동작한다 | 초안 |
| IN-F09 | 내장 터미널 | 앱을 떠나지 않고 Claude Code·Codex와 대화한다 | AC1: 프로젝트 폴더에서 셸을 열고 입력을 실행한다<br>AC2: Claude Code·Codex·셸을 탭으로 여러 개 실행하고, 다른 화면으로 옮겨도 실행 중인 터미널이 유지된다<br>AC3: 창 크기를 바꾸면 터미널 크기가 따라간다<br>AC4: 탭을 닫으면 프로세스가 종료되고 목록에서 빠진다<br>AC5: 다른 에이전트 세션 표시는 새 터미널 환경으로 넘기지 않는다<br>AC6: 모든 터미널 탭에서 Ctrl+V(macOS는 Cmd+V)로 텍스트를 붙여넣을 수 있고, 여러 줄 입력과 에이전트의 붙여넣기 모드를 유지한다 | 초안 |
| IN-F10 | 터미널 작업 끝 감지 | 터미널의 작업이 끝난 때를 안다 | AC1: Claude Code는 Stop 훅(준비는 SessionStart 훅), Codex는 notify로 응답 끝을 신호 파일에 남기게 실행한다 (사용자 설정은 그대로)<br>AC2: 신호 파일이 생기면 그 터미널의 응답 끝으로 알린다<br>AC3: 셸 명령이 끝나면 종료 코드와 함께 알린다 | 초안 |
| IN-F11 | 터미널 작업 그래프 | 터미널 작업이 끝나면 다음 작업이 저절로 이어진다 | AC1: 작업 그래프를 저장하고 다시 읽는다 (없는 노드를 잇는 선·자기 자신으로 가는 선은 버린다)<br>AC2: 고리, 빈 내용, 이어 쓸 앞 터미널이 없는 노드는 실행 전에 알려준다<br>AC3: 앞 작업이 끝나면 다음 작업을 실행하고, 갈래는 동시에, 모이는 곳은 모두 끝난 뒤에 실행한다<br>AC4: "이어서" 노드는 앞 노드의 터미널에 프롬프트를 보낸다<br>AC5: 셸 명령이 실패하거나 터미널이 닫히면 그 노드는 실패, 뒤 작업은 건너뛰고 다른 갈래는 계속한다<br>AC6: 중지하면 남은 작업을 보내지 않고, 신호를 놓친 노드는 직접 끝남으로 넘길 수 있다 | 초안 |
| IN-F12 | 작업 그래프 데이터 노드·템플릿 | 프롬프트를 조립하고, 자주 쓰는 흐름을 모듈로 재사용한다 | AC1: 텍스트·합치기 노드의 글이 데이터 선을 따라 실행 노드의 프롬프트 뒤에 붙는다 (위에 있는 입력부터)<br>AC2: 템플릿 노드는 실행할 때 템플릿의 지금 내용으로 펼쳐지고, 입력은 {{입력}} 자리에 들어간다<br>AC3: 없는 템플릿, 자기 자신을 다시 쓰는 템플릿은 실행 전에 알려주고, 쓰고 있는 템플릿은 지우지 않는다<br>AC4: 텍스트 노드에 글이 들어오면 적어 둔 글 대신 들어온 글을 내보내고, 할 일 노드에는 입력을 이을 수 없다 | 초안 |
| IN-F14 | 작업 그래프 시작 노드 | 어디서부터 실행되는지 그래프에서 보인다 | AC1: 직접 실행하는 그래프는 시작 노드가 있어야 하고, 템플릿은 없어도 된다<br>AC2: 시작에서 실행 선으로 닿는 노드만 실행하고, 닿지 않는 노드는 비어 있어도 실행을 막지 않는다<br>AC3: 템플릿 안에 시작 노드가 있으면 거기서부터 펼친다 | 초안 |
| IN-F15 | 작업 그래프 스킬 노드 | Claude Code 스킬을 프롬프트에 넣어 쓴다 | AC1: 프로젝트와 내 홈의 스킬을 읽는다 (폴더/SKILL.md와 바로 놓인 .md, frontmatter는 뺀 본문)<br>AC2: 스킬 노드는 스킬 본문을 글로 내보내 프롬프트에 붙이고, 입력은 받지 않는다 | 초안 |
| IN-F13 | 작업 그래프 할 일 노드 | 할 일을 가져와 처리하고 자동으로 완료한다 | AC1: 할 일 노드는 할 일의 제목·내용을 글로 내보내 프롬프트에 붙인다<br>AC2: "할 일 완료" 노드는 차례가 오면 이어진 할 일을 완료로 바꾸고 다음으로 넘어간다<br>AC3: 모든 종류의 노드와 고른 대상(ref)이 저장 후 그대로 읽힌다 | 초안 |

## 규칙

- 외부 원본은 고치지 않는다. Issue 생성 같은 쓰기는 사람이 요청했을 때만 한다.

## 미결정 사항

- Codex 세션 폴더 위치와 형식 확인
- 테스트 도구별 필터 인자 형식을 어떻게 설정받을지
