# Design

> 해결 문제: P1

## 역할

도메인의 기능을 어떻게 만들지 설계한다. 기능 하나에 속한 설계는 도메인 폴더 안에, 여러 기능이 함께 쓰는 결정은 시스템 공통 설계에 둔다. (3층: 설계)

## 용어

이 도메인(바운디드 컨텍스트) 안에서의 뜻이다. 같은 단어도 다른 도메인에서는 뜻이 다를 수 있다.

| 용어 | 뜻 | 비고 |
|---|---|---|
| 기능별 설계 | 기능 하나(또는 몇 개)의 구현 방법. 도메인 폴더의 `design/`에 둔다 | 필요한 기능만 작성 |
| 시스템 공통 설계 | 여러 기능이 함께 쓰는 결정. 프로젝트에 1개 (`system-design.md`) |  |
| 섹션 | 공통 설계 안의 단위. 기능별 설계가 참조하는 대상 |  |
| 기준 기능 버전 | 설계를 쓸 때 기준으로 삼은 기능 명세 표 버전 |  |
| 참조 (refs) | 기능별 설계가 공통 설계 섹션을 가리키는 것 |  |
| 낡음 | 기준 기능 또는 참조한 공통 설계 섹션에 큰 변경이 있었던 상태 | Spec의 낡음은 도메인 변경 기준 |

## 하지 않는 것

- 요구사항 정의 (설계는 기능을 참조만 한다)

## 다른 도메인과의 관계

| 방향 | 대상 | 내용 |
|---|---|---|
| 기준 | Spec | 설계는 기능의 표 버전을 기준으로 삼음 |
| 참조 | 시스템 공통 설계 | 공통 결정 섹션 참조 |
| 발행 | Impact Review | 설계 변경 알림 |
