# 할 일 기능 명세

나중에 할 일을 작업 유형과 시기를 붙여 보관하고, 때가 되면 다시 알려준다. (P2 해결)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| TK-F01 | 할 일 추가 | 떠오른 할 일을 놓치지 않는다 | AC1: 단축키로 한 줄을 입력하면 Inbox에 저장된다<br>AC2: 유형·시기 입력 없이 저장된다<br>AC3: 단축키부터 저장까지 입력 외 조작이 없다 | 초안 |
| TK-F02 | 에이전트 기록 | 작업 중 에이전트가 할 일을 남긴다 | AC1: `inbox/`에 생긴 md 파일이 Inbox 항목으로 표시된다<br>AC2: 파일에 적힌 출처 세션이 함께 기록된다 | 초안 |
| TK-F03 | 분류 | 할 일에 시기와 유형을 붙인다 | AC1: 유형과 시기를 고르면 Inbox 항목이 Task가 된다<br>AC2: 유형이나 시기가 없으면 Task로 저장되지 않는다<br>AC3: 관련 도메인·기능·AC를 연결할 수 있다<br>AC4: 필요 없으면 `버림`으로 닫을 수 있다 | 초안 |
| TK-F04 | Inbox 정리 알림 | 분류되지 않은 할 일이 쌓이지 않게 한다 | AC1: 설정 시각에 Inbox 항목이 있으면 알림이 뜬다<br>AC2: 항목이 없으면 알리지 않는다 | 초안 |
| TK-F05 | 시기 도래 알림 | 해야 할 때를 놓치지 않는다 | AC1: 기한이 지난 Task가 알림과 함께 첫 화면 상단에 표시된다<br>AC2: 트리거 조건(명세 활성, 도메인 변경, 다른 Task 완료)이 충족되면 같은 방식으로 표시된다 | 초안 |
| TK-F06 | 목록과 재검토 | 미뤄둔 일을 주기적으로 다시 본다 | AC1: 시기별·유형별·도메인별로 묶어 볼 수 있다<br>AC2: 주 1회 `나중`·`언젠가` Task 재검토 목록이 표시된다 | 초안 |
| TK-F07 | 상태 변경 | 진행 상황을 기록한다 | AC1: 상태는 대기 → 진행 → 완료 / 취소다<br>AC2: 완료 시 도메인 로직이 바뀌었는지 묻고, "예"면 도메인에 변경 요청을 보낸다 | 초안 |
| TK-F08 | 자동 생성 | 다른 도메인에서 생긴 할 일을 받는다 | AC1: 확인표시 보류·테스트 수정 필요 시 `spec-sync`/`design-sync`/`test` Task가 생성된다<br>AC2: 테스트에서 `test`/`bug` Task가 생성된다<br>AC3: 작업 대화에서 고른 할 일이 Inbox 항목으로 들어온다 | 초안 |
| TK-F09 | GitHub Issue 연동 | 저장소의 이슈와 할 일을 맞춘다 | AC1: Task로 Issue를 만들면 Task에 Issue 번호가 기록된다<br>AC2: 연결된 Issue가 닫히면 Task 완료를 제안한다 | 초안 |
| TK-F10 | 일정과 타임라인 | Task를 언제부터 언제까지 할지 한눈에 본다 | AC1: Task에 시작일·종료일을 넣고 고치고 지울 수 있다. 둘 다 선택이다<br>AC2: 종료일이 시작일보다 빠르면 저장되지 않고 오류가 뜬다<br>AC3: 타임라인 보기에서 시작일부터 종료일까지가 가로 막대로 보인다. 하나만 있으면 그 하루로 보이고, 둘 다 없으면 나오지 않는다<br>AC4: 시기 도래 알림은 기한만 보고 시작일·종료일은 보지 않는다 | 초안 |
| TK-F11 | Task 편집 | 만든 뒤에도 Task를 고치거나 지운다 | AC1: 제목, 유형, 시기, 상태, 시작일, 종료일, 기한, 연결, 내용(마크다운)을 고칠 수 있다<br>AC2: 제목이 비어 있으면 저장되지 않는다<br>AC3: Task를 지울 수 있고, 고치거나 지운 직후 되돌릴 수 있다<br>AC4: 편집 창에서 상태를 완료로 바꿔 저장해도 도메인 로직이 바뀌었는지 묻는다 | 초안 |
| TK-F12 | 완료 조건 체크 | 조건별 완료 여부를 따로 기록한다 | AC1: 본문의 마크다운 체크 항목을 완료 조건으로 표시하고 완료 개수를 보여 준다. 목록에서 펼쳐 체크·해제할 수 있다<br>AC2: 코드·HTML 예제는 제외하고, 선택한 체크 표시만 바꾸어 나머지 본문과 근거를 보존한다<br>AC3: 목록의 체크·해제는 즉시 저장되고 되돌릴 수 있다. 편집 창에서는 저장할 때 반영되며 취소하면 버린다<br>AC4: 조건의 완료 여부와 Task 전체 상태는 별도로 유지한다<br>AC5: 표시한 뒤 본문이 외부에서 바뀌었으면 덮어쓰지 않고 최신 내용 확인을 안내한다 | 초안 |

## 용어

| 용어 | 값 |
|---|---|
| 유형 | `feature` / `bug` / `refactor` / `tech-debt` / `research` / `docs` / `test` / `spec-sync` / `design-sync` / `domain-sync` |
| 시기 | `지금` / `다음` / `나중` / `언젠가` + 선택적 기한 또는 트리거 |

## 규칙

- Task는 반드시 유형과 시기를 가진다. Inbox 항목은 그렇지 않아도 된다.
- 상태 변경은 사람이 한다.
- 완료 조건은 본문의 `- [ ]`·`- [x]` 체크 항목으로 저장한다. 모든 조건을 체크해도 Task 전체 상태는 사람이 변경한다.
- 시작일·종료일은 작업 기간 표시용이고, 알림은 기한과 트리거만 본다.

## 미결정 사항

- 할 일 추가 단축키를 앱 밖(전역)에서도 쓸 수 있게 할지
