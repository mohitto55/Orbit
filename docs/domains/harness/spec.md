# Harness 기능 명세

도메인·명세·설계·지식을 Claude Code / Codex용 작업 환경 파일로 만들고, 원본이 바뀌면 다시 만들 때가 됐음을 알린다.

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| HN-F01 | 프로필 설정 | 에이전트별 생성 방식을 정한다 | AC1: 대상(Claude Code / Codex), 포함 내용, 생성 파일 종류를 고를 수 있다 | 초안 |
| HN-F02 | 생성 미리보기 | 덮어쓰기 사고를 막는다 | AC1: 생성될 내용과 현재 파일의 차이가 표시된다<br>AC2: 사람이 확인하기 전에는 파일을 쓰지 않는다 | 초안 |
| HN-F03 | 관리 영역 | 사용자가 직접 쓴 내용을 보존한다 | AC1: 생성 파일에서 앱은 관리 영역 표식 사이만 고친다<br>AC2: 표식 밖 내용은 생성 전후가 동일하다 | 초안 |
| HN-F04 | 기본 포함 내용 | 에이전트가 프로젝트 문서 체계를 따르게 한다 | AC1: 도메인 트리와 역할 요약, 원본 파일 위치가 포함된다<br>AC2: 활성 기능 명세 표와 설계 문서 위치가 포함된다<br>AC3: 하네스 포함 지식이 포함된다<br>AC4: "할 일은 `inbox/`에 파일로 남겨라" 안내가 포함된다<br>AC5: "테스트 이름에 AC ID(`[기능ID-AC번호]`)를 붙여라" 안내가 포함된다<br>AC6: "도메인 규칙이 바뀌는 작업이면 사람에게 알려라" 안내가 포함된다 | 초안 |
| HN-F05 | 낡음 알림 | 하네스가 원본과 어긋나지 않게 한다 | AC1: 생성 기준 이후 원본이 바뀌면 낡음이 표시되고 재생성을 묻는다<br>AC2: 도메인의 작은 변경으로는 알리지 않는다 | 초안 |
| HN-F06 | 생성 이력 | 언제 무엇으로 만들었는지 추적한다 | AC1: 생성 시각과 기준 버전 목록이 기록된다 | 초안 |

## 규칙

- 하네스는 원본을 복제하지 않고 요약·안내한다. 자세한 내용은 원본 파일 위치로 안내한다.
