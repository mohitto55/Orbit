# Orbit

도메인 모델, 기능 명세, 설계, 테스트, 나중에 할 일을 한곳에서 관리하는 데스크톱 앱. 앱 안 터미널에서 Claude Code / Codex로 작업하고, 그 대화를 도메인 모델과 비교할 수 있다.

위 층 문서가 바뀌면 아래 층에 **확인표시**를 띄워, 도메인과 명세와 코드가 서로 어긋나지 않게 한다.

```
도메인 (역할) ──기준──▶ 기능 명세 표 (요구사항 + AC) ──기준──▶ 설계
                               │
                               └──검증──▶ 테스트 (이름에 AC ID)
```

## 설치

[Releases](../../releases)에서 운영체제에 맞는 파일을 받는다.

| OS | 파일 |
|---|---|
| Windows | `Orbit-Setup-x.y.z.exe` |
| macOS | `Orbit-x.y.z.dmg` |
| Linux | `Orbit-x.y.z.AppImage` |

설치 후에는 새 버전이 나오면 자동으로 업데이트된다.

## 주요 기능

| 화면 | 하는 일 |
|---|---|
| 도메인 | 도메인 트리 (하위 도메인의 상위는 하나), 도메인별 역할·용어, 기능 명세 표, 기능별 설계, 변경 이력 |
| 변경 검토 | 위 층이 크게 바뀌어 생긴 확인 항목을 위 층 변경 내역과 나란히 보고 `변경 불필요` / `수정 필요` / `보류` 처리 |
| 할 일 | 할 일 추가(Inbox, `Ctrl+Shift+Space`) → 유형·시기를 붙여 Task로. 기한·트리거가 되면 알림 |
| 테스트 | 테스트 명령 실행, JUnit 결과를 AC 단위로 표시 (통과 / 실패 / 테스트 없음 / 확인 필요) |
| 도메인 점검 | 주기적으로 Claude Code / Codex 대화와 도메인을 나란히 보여주고, 사람이 표시한 부분을 도메인 변경 요청·할 일·지식으로 넘김 |
| 지식 | 결정(ADR), 프로젝트 용어, 컨벤션, 교훈 |
| 터미널 | 프로젝트 폴더에서 Claude Code · Codex · 셸을 탭으로 실행. 실행 명령 설정, 이름 변경, 앱 재시작 시 탭·세션 자동 복원 |
| 관계도 | 문서를 노드로, 관계를 링크로. 전체 / 로컬 / 계층 보기, `[[이름]]` 링크와 미정의 노드 |

도메인 그래프의 모델 관계는 참조하는 개념에서 참조 대상 개념으로 직접 이어진다. 소속 도메인이 달라도 애그리거트 루트로 합치지 않으며, 화살표로 방향을 표시한다. 같은 두 개념 사이의 서로 다른 관계와 반대 방향 참조도 각각 유지한다.

할 일 상세·도메인·설계·지식·수정안은 **마크다운 원문으로 직접 편집**한다. Enter로 한 줄을 바꾸며 제목·목록·표·코드 블록과 빈 줄을 그대로 작성할 수 있다. **미리보기**에서 렌더링된 모습을 확인하고 편집으로 돌아와 이어 쓸 수 있다.

터미널은 화면을 옮겨도 실행이 유지된다. Orbit을 종료하면 작업은 중단된다. 앱을 다시 켜면 먼저 프로젝트 폴더 선택 화면이 나오고, 같은 프로젝트를 선택하면 열어 두었던 터미널 탭·이름·선택 상태와 CLI 세션을 자동으로 복원한다. 일반 터미널에서 직접 실행한 Claude Code·Codex도 복원 대상이며, CLI에서 기존 대화를 선택했다면 그 세션으로 재개한다. 대화 목록을 따로 고를 필요가 없고, Orbit은 대화 본문을 가져오지 않는다. CLI가 실행 중이지 않은 일반 셸은 탭과 최근 출력을 복원한다. 사용자가 닫은 탭은 다시 열지 않는다.

이전 버전에서 세션 ID 없이 저장된 일반 터미널 탭은 업데이트 후 CLI에서 한 번 재개해야 한다. 이후부터 해당 세션이 자동으로 복원된다.

데이터가 많은 프로젝트도 전체 소스 검사를 기다리지 않고 화면부터 연다. 필요한 변경 검토는 뒤에서 복원하고, 빌드 산출물과 캐시는 테스트 탐색에서 제외한다. 터미널 세션은 차례로 자동 복원하며, 각 터미널 화면은 해당 탭을 처음 선택할 때 준비한다. 복원 도중 프로젝트를 닫아도 저장된 탭과 최근 출력은 유지한다.

터미널 탭과 사용자 그룹은 **드래그로 순서 변경**이 가능하다. 놓을 위치를 표시하며 바꾼 순서는 프로젝트별로 저장한다. 탭을 그룹 위에 놓으면 해당 그룹으로 옮겨지고, 각 그룹 옆 **연필 버튼**으로 이름을 바꿀 수 있다. 전체·미분류 필터는 맨 앞에 고정된다. 순서와 이름을 바꿔도 실행 중인 세션·출력과 선택 상태는 유지된다.

컴퓨터에 저장된 **사진·파일을 터미널 화면에 드래그**하면 선택한 세션의 입력창에 추가한다. 여러 파일과 공백·한글이 들어간 경로를 지원하며, Codex·Claude가 인식하는 이미지는 첨부로 들어간다. 일반 셸에는 인용한 경로를 넣는다. 내용을 확인하고 Enter를 눌러 전송한다.

세션 이름 왼쪽 점은 **주황색: 작업 중**, **초록색: 작업 완료·미확인**, **회색: 기본 상태**를 표시한다. 완료된 터미널을 실제로 열어 보면 회색으로 돌아간다. 다른 탭·다른 화면·작업 그래프·비활성 창을 보는 동안에는 완료 알림이 남으며, 앱을 다시 열어도 미확인 완료 상태를 유지한다.

작업 그래프의 **세션 불러오기** 목록은 해당 세션에 저장된 이름을 우선 표시하며, 이름이 없으면 첫 메시지를 표시한다. **터미널 탭 이름**은 생성할 때 정한 이름이나 사용자가 수정한 이름을 저장해 유지한다. AI가 세션 이름을 바꾸거나 앱을 재시작·재연결하거나 다른 세션을 불러와도 탭 이름은 바뀌지 않는다.
선택한 세션이 Orbit에서 이미 실행 중이면 기존 터미널 탭을 그대로 사용한다. 실행 중인 탭이 없을 때만 새 탭을 연다.
Codex에는 긴 프롬프트도 붙여넣기를 확정한 뒤 자동 전송한다. 입력 길이에 따라 CLI가 내용을 받는 데 시간이 걸릴 수 있지만, 전송을 위해 Enter를 다시 누를 필요는 없다.

**데이터 → 터미널**에서 열려 있는 탭을 고르고 Codex·Claude Code 노드의 **터미널 입력 핀**에 연결하면 그 탭에서 실행한다. 노드의 터미널 출력 핀을 다음 노드에 연결하거나 함수의 입출력 타입을 **터미널**로 지정해 같은 탭을 전달할 수도 있다. 실행 순서는 실행 선으로 연결한다. 터미널 연결은 새 탭·세션 불러오기·이어서 설정보다 우선하며, 닫힌 탭이나 종류가 다른 탭을 새 탭으로 대체하지 않는다.

작업 그래프의 리스트에서 항목을 **꺼내기**로 만들면 원본 출력과 항목 입력이 자동으로 연결된다. 항목 노드는 지정한 인덱스의 현재 값을 읽으므로 원본을 고치면 함께 바뀐다.

Claude·Codex 노드에서 **출력 형식 → 구조화된 JSON**을 고르면 **Field name·Type·Description**을 지정할 수 있다. 기본 필드는 `result`이고 타입은 **String·Number·Boolean·Object·Array·Null**로 표시한다. **Array**는 **Items**에서 항목 타입을, **Object**는 **Properties**에서 내부 필드를 정의한다. `Array<Object>`와 중첩 Array도 편집·저장하며, 응답의 모든 항목을 검사해 틀린 위치를 `items[1].value`처럼 알린다. 별도의 **출력 구조** 데이터 노드를 만들어 에이전트의 같은 이름 핀에 연결해도 된다. 기존 필드 이름과 내부 타입을 제한하지 않았던 구조는 유지한다.

**유틸리티 → Print**는 실행 입력·출력과 값 입력이 있는 노드다. 텍스트·리스트·JSON·Bool·숫자 값을 연결하거나 직접 적고 실행 선을 연결하면, 실행 시점의 값을 **하단 출력 로그**에 남기고 다음 노드로 넘어간다. Claude·Codex 응답과 셸 출력도 같은 로그에 완료 순서대로 표시된다. **Print만** 필터, 복사, 출력한 노드 선택을 지원하며 반복·함수 안의 출력도 구분한다. 로그는 현재 앱에서 그래프별 마지막 실행을 보여 준다.

작업 그래프의 **왼쪽 목록·오른쪽 속성·하단 출력 로그**는 경계를 마우스로 드래그해 크기를 조절한다. 크기는 다시 열 때도 유지하며 그래프의 노드 위치·확대 비율은 그대로다. 경계를 더블클릭하면 해당 패널을, **레이아웃 초기화**를 누르면 전체 크기를 기본값으로 되돌린다. 경계에 키보드 포커스를 두고 방향키로도 조절할 수 있다.

**+ 결과 Dictionary**를 누르면 응답 핀에 연결된 데이터 노드가 생긴다. 실행 후 Object·Array를 펼쳐 확인하고 **꺼내기**로 키나 인덱스를 별도 **JSON 필드** 노드로 만든다. `/items/0/value`처럼 중첩 경로도 선택할 수 있고, 원본을 고치거나 다시 실행하면 새 값을 읽는다. 결과를 사용하는 다음 작업에는 실행 선도 연결해야 한다. 선언한 필드는 모두 필수이며, JSON 오류·키 누락·추가 키·타입 불일치는 해당 작업을 실패로 처리한다. 실행 결과는 앱이 열린 동안 유지되고, 노드 설정과 연결은 저장된다.

최종 응답 수집에는 [Codex 완료 알림](https://developers.openai.com/codex/config-advanced#notifications)과 [Claude Code Stop 훅](https://code.claude.com/docs/en/hooks#stop)을 사용한다. 일반 터미널의 대화 기록은 가져오지 않으며, 그래프가 요청한 응답만 수집한다.

**데이터 → 텍스트 Add**는 A와 B 입력의 텍스트를 `A + B` 순서로 이어 붙인다. 각 입력에 텍스트 출력 핀을 연결하거나 기본값을 직접 적고, 결과 핀을 다음 노드에 연결한다. 노드 위치를 바꿔도 순서는 유지되며 공백·줄바꿈은 입력한 그대로 들어간다. 우클릭 검색에서 `add`로도 찾을 수 있다.

기존 템플릿은 **함수**로 표시한다. 새 함수에는 삭제할 수 없는 **Input·Output** 노드가 있고, 각 노드에서 변수 이름과 타입(텍스트·텍스트 리스트·터미널·JSON·출력 구조·Bool·숫자)을 추가·변경한다. Input의 변수 출력 핀을 내부 노드에 연결하고, 반환할 값을 Output의 변수 입력 핀에 연결한다. 실행 선도 Input에서 시작해 Output으로 이어야 한다. 다른 그래프의 함수 호출 노드에는 같은 변수 핀이 생기며, 연결하지 않은 입력에는 기본값을 적을 수 있다. 변수 이름을 바꿔도 연결은 유지되고, 타입이 다른 연결은 실행 전에 알려 준다. 예전 템플릿의 실행 흐름과 `{{입력}}`은 그대로 사용할 수 있다.

리스트를 함수에 연결할 때는 **텍스트 리스트** 타입의 입력을 사용한다. 노드 본체에 놓거나 핀에서 함수 생성 메뉴를 열어 연결하면 타입이 맞는 입력을 찾는다. 화면을 축소해도 누른 변수 핀에서 선을 끌 수 있다.

**유틸리티 → For Each**는 리스트를 한 항목씩 순서대로 처리한다. `반복 본문` 핀에 실행할 작업을 연결하고, `항목`·`인덱스 (0부터)` 핀을 본문에서 사용한다. 한 항목의 모든 작업이 끝나면 다음 항목으로 넘어가며, 빈 리스트이거나 모든 항목을 마치면 `완료` 핀을 실행한다. 본문 끝을 For Each로 다시 연결할 필요는 없다. 함수 안에서 사용하거나 반복을 중첩할 수도 있다.

**유틸리티 → If**는 **Bool 조건**을 받아 `True (참)` 또는 `False (거짓)` 실행 핀으로 분기한다. **비교** 노드(`==`, `!=`, `>`, `>=`, `<`, `<=`)나 **AND·OR·NOT** 노드의 빨간 Bool 출력을 If의 조건 핀에 연결한다. 예를 들어 `숫자 비교 A=10, B=2, > → If 조건`이면 True 경로를 실행한다. 비교 타입은 숫자·텍스트·Bool이며 크기 비교는 숫자만 지원한다. 텍스트의 같음 비교는 대소문자·공백도 구분한다.

**Bool·숫자** 데이터 노드에는 값을 직접 지정하거나, 응답 텍스트·JSON 필드를 연결해 명시적으로 변환할 수 있다. Bool은 `true`·`false`만 허용하고 숫자는 유효한 유한 값만 허용한다. 연결되지 않은 Bool·숫자 입력의 기본값은 `false`·`0`이다. 선택하지 않은 분기는 건너뛰고, 합류 지점은 선택된 작업들이 끝나면 한 번 실행한다. For Each에서 연결되지 않은 분기는 다음 항목으로, 함수에서는 반환으로 이어진다. 선택된 작업이 실패하면 뒤 작업도 건너뛰며, 실행하지 않은 작업의 응답은 사용할 수 없다.

설정의 **터미널**에서 Claude Code·Codex 실행 명령과 대화 재개 명령을 바꿀 수 있다. 재개 명령의 `{sessionId}`는 해당 탭의 세션 ID로 바뀐다. 재개 명령을 비워 두면 실행 명령 뒤에 Claude는 `--resume {sessionId}`, Codex는 `resume {sessionId}`를 붙인다.
Codex 탭은 `--no-daemon`을 지원하는 CLI로 독립 실행하여 각 탭의 세션 ID와 저장 위치를 유지한다.

```
  domains/<도메인>/    domain.md · spec.md · design/<기능ID>.md
  changes/            변경 기록 (추가만 함)

```

이 저장소의 [`docs/`](docs/domain-model.md)는 Orbit 자신을 Orbit으로 관리한 데이터 폴더다.

## 테스트와 AC 연결

테스트 이름에 검증하는 수용 기준 ID를 붙이면 앱이 연결을 찾는다.

```ts
it('[TK-F03-AC2] 유형이나 시기가 없으면 Task로 저장되지 않는다', ...)
```

프로젝트 설정의 테스트 명령은 JUnit XML을 만들어야 한다. 예: `npx vitest run --reporter=junit --outputFile.junit=test-results/junit.xml`

## 개발

```bash
npm install
npm run dev         # 개발 모드 실행
npm test            # 핵심 로직 테스트
npm run typecheck
npm run dist        # 현재 OS용 설치 파일 (release/)
```

릴리스: `v*` 태그를 push하면 GitHub Actions가 세 OS용 설치 파일을 만들어 Releases에 올린다.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

구조: `src/core` (md 기반 도메인 로직, Electron 의존 없음) · `src/main` (Electron 메인, IPC, 파일 감시, 테스트 실행) · `src/renderer` (React 화면).
