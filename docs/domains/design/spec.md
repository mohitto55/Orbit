# Design 기능 명세

기능을 어떻게 만들지 설계한다. 기능별 설계와 시스템 공통 설계를 구분한다. (3층)

| ID | 기능 | 목적 | 수용 기준 | 상태 |
|---|---|---|---|---|
| DS-F01 | 기능별 설계 만들기 | 복잡한 기능의 구현 방법을 정리한다 | AC1: 기능 명세 표의 행에서 바로 설계를 만들 수 있다<br>AC2: 설계는 하나 이상의 기능 ID를 기준으로 가지며, 각 기능의 현재 표 버전이 기준 버전으로 기록된다<br>AC3: 설계가 없는 기능도 허용된다 (필요할 때만 작성) | 초안 |
| DS-F02 | 설계 본문 형식 | 설계 내용을 일관되게 쓴다 | AC1: 기본 섹션은 개요 / 처리 흐름 / 데이터 / 인터페이스(API) / 예외 처리 / 대안과 선택 이유다<br>AC2: 템플릿은 프로젝트 설정에서 바꿀 수 있다 | 초안 |
| DS-F03 | 시스템 공통 설계 | 여러 기능이 함께 쓰는 결정을 한곳에 둔다 | AC1: 프로젝트마다 1개 존재한다<br>AC2: 기본 섹션은 비기능 요구사항 / 규모 산정 / 전체 구조 / 공통 기술 결정이다 | 초안 |
| DS-F04 | 공통 설계 참조 | 공통 결정을 기능별 설계에서 반복하지 않는다 | AC1: 기능별 설계에서 공통 설계의 섹션을 링크로 참조할 수 있다<br>AC2: 참조한 섹션이 기록된다 (영향 검토용) | 초안 |
| DS-F05 | 변경 기록 | 설계가 바뀐 이유를 남긴다 | AC1: 저장 시 변경 크기와 요약을 입력해야 한다<br>AC2: 버전이 1 오르고 ChangeSet이 남는다<br>AC3: 공통 설계는 변경 내역에 바뀐 섹션이 기록된다 | 초안 |
| DS-F06 | 낡음 표시 | 요구사항과 어긋난 설계를 드러낸다 | AC1: 기준 기능에 큰 변경이 있으면 설계에 낡음이 표시된다<br>AC2: 참조한 공통 설계 섹션에 큰 변경이 있어도 낡음이 표시된다 | 초안 |

## 규칙

- 설계는 요구사항을 정의하지 않는다. 요구사항이 바뀌어야 하면 기능 명세 표를 먼저 고친다.
- 여러 기능별 설계에 같은 내용이 반복되면 공통 설계로 옮긴다.

## 미결정 사항

- 공통 설계를 섹션 단위로 쪼개 여러 파일로 둘지 (규모가 커질 때)
