# Spec

> 해결 문제: P1

## 역할

도메인마다 기능 명세 표를 두고, 기능별 요구사항과 수용 기준(AC)을 관리한다. 어떤 도메인 버전을 기준으로 썼는지 기억한다. (2층: 요구사항)

## 용어

이 도메인(바운디드 컨텍스트) 안에서의 뜻이다. 같은 단어도 다른 도메인에서는 뜻이 다를 수 있다.

| 용어 | 뜻 | 비고 |
|---|---|---|
| 기능 명세 표 | 도메인 하나의 요구사항 목록. 도메인당 1개 |  |
| 기능 (Feature) | 표의 한 행. ID는 `도메인코드-F번호` |  |
| 수용 기준 (AC) | 기능이 됐다고 판단하는 관찰 가능한 조건. ID는 `기능ID-AC번호` | 테스트가 가리키는 대상 |
| 기준 버전 | 표를 쓸 때 기준으로 삼은 도메인 버전 |  |
| 낡음 | 기준 버전 이후 도메인에 **큰 변경**이 있었던 상태 | Design·Harness의 낡음과 조건이 다르다 |
| 재확인 | 내용은 그대로 두고 기준 버전만 현재 도메인 버전으로 올리는 것 |  |
| 행 상태 | `초안` / `활성` / `폐기` | 초안 행은 변경 기록 없이 고칠 수 있다 |
| 검증 상태 | Verification이 알려준 AC별 결과 | Spec은 표시만 하고 판단하지 않는다 |

## 하지 않는 것

- 도메인 정의, 구현 방법 서술 (→ Design)

## 다른 도메인과의 관계

| 방향 | 대상 | 내용 |
|---|---|---|
| 기준 | Domain Modeling | 표는 도메인 버전을 기준으로 삼음 |
| 발행 | Impact Review | 바뀐 기능·AC 알림 |
| 수신 | Verification | AC별 검증 결과 |
| 수신 | Impact Review | 확인 결과 반영 요청 |
