# 도메인

> 해결 문제: P1

## 역할

프로젝트의 도메인과 하위 도메인, 그 안의 개념을 정의하고 버전을 관리한다. (1층: 역할)

## 용어

이 도메인(바운디드 컨텍스트) 안에서의 뜻이다. 같은 단어도 다른 도메인에서는 뜻이 다를 수 있다.

| 용어 | 뜻 | 비고 |
|---|---|---|
| 도메인 | 역할과 경계를 가진 업무 영역. 하위 도메인도 같은 종류다 |  |
| 하위 도메인 | 상위 도메인이 정확히 하나인 도메인 |  |
| 상위 도메인 (parent) | 하위 도메인이 속한 도메인. 하나뿐이다 |  |
| 도메인 유형 | `Core` / `Supporting` / `Generic`. 전략적 중요도 |  |
| 개념 (Concept) | 도메인 안의 Entity / Value Object / Aggregate / Event / Policy / Term. 정확히 한 도메인에 속한다 | Term은 이 도메인 안에서만 유효한 용어 |
| 버전 | 도메인 문서의 정수 버전. 저장할 때마다 1 오른다 | 개념에는 버전이 없다 |
| 변경 크기 | `큰 변경`(규칙·구조 변경, 이동) / `작은 변경`(설명 보강, 오타) | 큰 변경만 아래 층 문서에 영향을 준다 |
| ChangeSet | 저장 1회의 기록. 변경 크기, 요약, 출처, 바뀐 항목 |  |
| 경로 표기 | 상위부터 이어 쓴 이름 (`주문 › 고객`) | 이름이 겹칠 때 구분용. 식별자는 아니다 |
| 폐기됨 | 더 쓰지 않지만 이력 보존을 위해 남긴 도메인 |  |
| 변경 요청 | 도메인에 반영해 달라고 들어온 요청. 사람이 반영하면 요청의 출처와 함께 변경 기록이 남는다 | 도메인이 받아서 반영한다 |

## 하지 않는 것

- 변경이 다른 문서에 미치는 영향 판단
